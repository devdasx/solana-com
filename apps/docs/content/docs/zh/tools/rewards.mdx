Rewards 程序会将代币从程序所有的金库分发给一组接收者，每位接收者都有各自的归属计划。授权方为金库注入资金并定义谁获得多少。接收者随时间推移领取已归属的代币；在分发配置允许的情况下，授权方可以撤销接收者或收回剩余代币。该程序使用 Pinocchio 构建，由 Solana 基金会维护，支持 SPL Token 和 Token-2022 mint，但不支持启用了 transfer hook 扩展的 Token-2022 mint。

## 选择分发类型

该程序支持两种分发类型，二者使用相同的归属计划和撤销模式。

|                  | Direct（直接）                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **工作方式** | 为每位接收者创建一个链上账户     | 在链上仅存储一个 Merkle 根；接收者提供证明来领取  |
| **前期成本** | 付款方为每个接收者账户支付 rent | 在有人领取之前，不会创建任何接收者账户                           |
| **规模**        | 适用于数千名以内的接收者  | 可扩展至数百万名接收者；存储仅随领取者的领取而增长 |
| **可变性**   | 创建后仍可添加接收者       | 接收者集合在创建时即固定                                       |
| **适用场景**   | 会随时间变化的小规模分发    | 空投等大规模、固定的分发                              |

## 归属计划

每笔分配都采用以下四种计划之一。时间戳均为 Unix 秒。

| 计划      | 行为                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | 所有代币可立即领取                                                                                    |
| `Linear`      | 代币在 `startTs` 与 `endTs` 之间按比例解锁                                                             |
| `Cliff`       | 在 `cliffTs` 之前不会解锁任何代币，到达后全部一次性解锁                                                       |
| `CliffLinear` | 从 `startTs` 到 `endTs` 线性归属，但在 `cliffTs` 之前无法领取任何代币；此前累积的部分在悬崖时间点解锁 |

## 账户

| 账户              | PDA seeds                                        | 存储内容                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | 授权方、mint 和分配总额       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | 单个接收者的分配和归属情况       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | 授权方、mint、总额以及 Merkle 根 |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | 单个领取者截至目前已领取的数量        |
| `Revocation`         | `["revocation", distribution, user]`             | 用于阻止已被撤销的 Merkle 领取者的标记 |

`seed` 是创建时传入的额外签名者的地址，因此同一个授权方可以为同一个 mint 运行多个分发。每个分发的金库是该 mint 对应的分发 PDA 的 associated token account。

## 指令

### Direct 分发

1. 授权方调用 `CreateDirectDistribution` 来创建分发 PDA 及其金库。
2. 授权方为每位接收者调用一次 `AddDirectRecipient`，并指定数量和归属计划。每次调用都会将相应数量的代币从授权方的 token account 转入金库。
3. 接收者调用 `ClaimDirect` 提取已归属的代币。传入 `amount: 0` 即可领取当前所有已归属的代币。
4. 当接收者领取完所有代币或分发已关闭后，`CloseDirectRecipient` 会关闭接收者账户，并将 rent 退还给支付该费用的账户。
5. 授权方调用 `CloseDirectDistribution` 来回收金库中的剩余余额和 rent。如果设置了 `clawbackTs`，则只有在该时间之后才允许关闭。

### Merkle 分发

1. 授权方在链下构建 Merkle 树。每个叶子节点承诺包含领取者、该领取者的总额以及归属计划。
2. 授权方使用根、可领取总额和 `clawbackTs` 调用 `CreateMerkleDistribution`，并在同一条指令中为金库注资。
3. 领取者使用其叶子数据和证明调用 `ClaimMerkle`。首次领取会创建该领取者的 `MerkleClaim` 账户。传入 `amount: 0` 即可领取当前所有已归属的代币。
4. 在 `clawbackTs` 之后，授权方调用 `CloseMerkleDistribution` 来回收金库中的剩余余额和 rent。
5. 分发关闭后，领取者调用 `CloseMerkleClaim` 来回收其领取账户的 rent。

程序使用 Keccak-256 对叶子节点进行哈希，计算方式为 `keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`，其中 `totalAmount` 为小端序的 `u64`，`schedule` 采用与指令的 `VestingSchedule` 参数相同的编码。证明节点按排序后的配对进行哈希，较小的哈希在前。

### 撤销

撤销功能需要主动启用。创建时设置的 `revocable` 位掩码决定授权方可使用的模式：位 0 启用 `NonVested`，位 1 启用 `Full`，`0` 表示禁用撤销。

| 模式        | 指令                                    | 结果                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` 或 `RevokeMerkleClaim` | 已归属但未领取的代币归用户所有；未归属的代币退回授权方 |
| `Full`      | `RevokeDirectRecipient` 或 `RevokeMerkleClaim` | 所有未领取的代币（无论是否已归属）都退回授权方               |

撤销 Merkle 领取者会创建一个 `Revocation` 标记，即使该领取者从未领取过，也会阻止其日后领取。撤销 Direct 接收者则会关闭其 `DirectRecipient` 账户并退还其 rent。
