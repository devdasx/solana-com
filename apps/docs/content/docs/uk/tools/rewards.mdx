Програма Rewards розподіляє токени зі сховища (vault), що належить програмі, між
набором одержувачів, кожен з яких має власний графік вестингу. Authority поповнює
vault і визначає, хто що отримує. Одержувачі з часом забирають свої розблоковані
токени, а authority може відкликати одержувачів або повернути залишок токенів,
якщо розподіл це дозволяє. Програму створено за допомогою Pinocchio, її підтримує
Solana Foundation, і вона працює з mint-ами як SPL Token, так і Token-2022, окрім
mint-ів Token-2022 із розширенням transfer hook.

ID програми (mainnet і devnet):

```text
REWArDioXgQJ2fZKkfu9LCLjQfRwYWVVfsvcsR5hoXi
```

## Оберіть тип розподілу

Програма підтримує два типи розподілу. Обидва використовують однакові графіки
вестингу та режими відкликання.

|                  | Прямий (Direct)                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **Як це працює** | Створює ончейн-акаунт для кожного одержувача     | Зберігає ончейн єдиний корінь Меркла; щоб отримати токени, одержувачі надають proof  |
| **Початкові витрати** | Платник сплачує rent за акаунт кожного одержувача | Жодних акаунтів для окремих одержувачів, доки хтось не забере токени                           |
| **Масштаб**        | Практично до кількох тисяч одержувачів  | Масштабується до мільйонів одержувачів; обсяг сховища зростає лише в міру того, як одержувачі забирають токени |
| **Змінність**   | Одержувачів можна додавати після створення       | Набір одержувачів фіксується під час створення                                       |
| **Для чого підходить**   | Невеликі розподіли, що змінюються з часом    | Великі фіксовані розподіли, як-от airdrop                              |

## Графіки вестингу

Кожен розподіл має один із чотирьох графіків. Позначки часу — це секунди Unix.

| Графік      | Поведінка                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | Усі токени доступні для отримання одразу                                                                                    |
| `Linear`      | Токени розблоковуються пропорційно між `startTs` і `endTs`                                                             |
| `Cliff`       | Нічого не розблоковується до `cliffTs`, після чого все розблоковується одразу                                                       |
| `CliffLinear` | Лінійний вестинг від `startTs` до `endTs`, при цьому нічого не можна забрати до `cliffTs`; раніше нараховані токени розблоковуються в момент cliff |

## Акаунти

| Акаунт              | PDA seeds                                        | Зберігає                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | Authority, mint і загальні суми розподілу       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | Розподіл і вестинг одного одержувача       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | Authority, mint, загальні суми та корінь Меркла |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | Сума, яку вже отримав один claimant        |
| `Revocation`         | `["revocation", distribution, user]`             | Маркер, що блокує відкликаного claimant-а Merkle |

`seed` — це адреса додаткового підписанта, яку передають під час створення, тож
один authority може запускати кілька розподілів для того самого mint. Vault
кожного розподілу — це associated token account PDA розподілу для його mint.

## Інструкції

### Прямий розподіл

1. Authority викликає `CreateDirectDistribution`, щоб створити PDA розподілу
   та його vault.
2. Authority викликає `AddDirectRecipient` один раз для кожного одержувача, вказуючи
   суму та графік вестингу. Кожен виклик переказує цю суму з token account
   authority до vault.
3. Одержувачі викликають `ClaimDirect`, щоб вивести розблоковані токени. Передайте
   `amount: 0`, щоб забрати все, що наразі розблоковано.
4. Коли одержувач забрав усе або розподіл закрито, `CloseDirectRecipient` закриває
   акаунт одержувача й повертає rent акаунту, який за нього заплатив.
5. Authority викликає `CloseDirectDistribution`, щоб повернути залишок на балансі
   vault і rent. Якщо задано `clawbackTs`, закрити розподіл можна лише після
   цього моменту.

### Розподіл Merkle

1. Authority будує дерево Меркла офчейн. Кожен лист фіксує claimant-а, загальну
   суму цього claimant-а та графік вестингу.
2. Authority викликає `CreateMerkleDistribution`, передаючи корінь, загальну суму,
   доступну для отримання, і `clawbackTs`, та поповнює vault в тій самій
   інструкції.
3. Claimant-и викликають `ClaimMerkle`, передаючи дані свого листа та proof. Перше
   отримання створює акаунт `MerkleClaim` claimant-а. Передайте `amount: 0`, щоб
   забрати все, що наразі розблоковано.
4. Після `clawbackTs` authority викликає `CloseMerkleDistribution`, щоб повернути
   залишок на балансі vault і rent.
5. Після закриття розподілу claimant-и викликають `CloseMerkleClaim`, щоб повернути
   rent за свій акаунт claim.

Програма хешує листи за допомогою Keccak-256 як
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`, де
`totalAmount` — це `u64` у little-endian, а `schedule` використовує те саме
кодування, що й аргумент `VestingSchedule` інструкції. Вузли proof хешуються як
відсортовані пари, спочатку менший хеш.

### Відкликання

Відкликання вмикається за бажанням. Бітова маска `revocable`, задана під час
створення, визначає, які режими може використовувати authority: біт 0 вмикає
`NonVested`, біт 1 вмикає `Full`, а `0` вимикає відкликання.

| Режим        | Інструкція                                    | Результат                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` або `RevokeMerkleClaim` | Розблоковані, але не отримані токени надходять користувачеві; ще не розблоковані токени повертаються authority |
| `Full`      | `RevokeDirectRecipient` або `RevokeMerkleClaim` | Усі неотримані токени, розблоковані й нерозблоковані, повертаються authority               |

Відкликання claimant-а Merkle створює маркер `Revocation`, який блокує подальші
отримання, навіть якщо він ще жодного разу не забирав токени. Відкликання
прямого одержувача закриває його акаунт `DirectRecipient` і повертає rent.

## Клієнти

Репозиторій містить клієнти [`@solana/kit`](/docs/clients/official/javascript) та
Rust, згенеровані з IDL програми за допомогою Codama, у
[`clients/`](https://github.com/solana-foundation/rewards/tree/main/clients).
Клієнт ще не опубліковано в npm. Зберіть його з вихідного коду за допомогою
`just generate-clients`.
